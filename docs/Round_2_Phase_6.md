# Round 2 phase 6 — offline acceptance infrastructure and release gates

This phase implements and runs the authorized local acceptance work from [the reviewed plan](Topsl_Round_2_Improvement_Plan_Reviewed.md#11-phase-r2-6--live-acceptance-and-release-qualification). Its provider responses are deterministic dependency-injected fixtures. Its dependency preparation and project checks are actual local subprocesses. Live Codex → Claude and Claude → Codex acceptance, an actual delivery commit, and the four platform jobs remain pending. This document does not declare the round complete.

## Reproducible demonstration project

`scripts/round2-demo-fixture.mjs` creates a new disposable Git repository. It refuses to reuse an existing directory. Git initialization and commits occur only inside that fixture, using a fixture identity and disabled global Git configuration. It does not alter Topsl's branch or index.

The generated project contains multiple JavaScript modules, TypeScript contracts, over 1,200,000 bytes of reference source, a tracked PNG, a tracked `build/receipt.mjs`, and original executable acceptance checks. A deterministic local `.tgz` supplies `@topsl/demo-money`, locked by a SHA-512 integrity record. Generation does not run npm or a package hook. Verification later runs the selected installed Node/npm with a fresh disposable install of this archive; it does not fetch a registry package or copy developer `node_modules`.

The requested feature needs a new `src/discount.mjs`. The builder fixture first implements a twenty percent discount, while the original checks require ten percent. The exact new-file hash must be approved before review/checks. The actual project check fails with 800 versus 900 cents. One bounded repair changes the module to ten percent, preserves the original cart check and tracked build script, and creates new candidate, review, and verification evidence. An unchanged binary image remains in both candidates. Provider labels reverse in the second case, exercising the same provider-neutral coordinator in both directions.

Create a standalone input project:

```sh
node scripts/round2-demo-fixture.mjs
node scripts/round2-demo-fixture.mjs --root /absolute/new/disposable-directory --seed topsl-round2-v1
node --test tests/round2-demo-fixture.test.mjs
```

The command prints the disposable path, base commit, source identity, logical bytes and file count. The fixture test verifies deterministic input hashes, local dependency resolution, tracked assets/build source, missing feature output, and refusal to overwrite an existing directory.

## Acceptance runner and retained artifacts

Run with the already installed Topsl engineering toolchain:

```sh
node scripts/round2-acceptance.mjs
node scripts/round2-acceptance.mjs --stress
node scripts/round2-acceptance.mjs --only-stress
node scripts/round2-acceptance.mjs --only-crash
```

Each invocation creates a unique directory under `docs/round-2-evidence/`. An optional `--output /absolute/new/directory` also requires a nonexistent directory. The script has no live-provider command or API fallback. Provider requests and billed inference usage are zero for these runs. Actual checks execute with the disclosed `user-approved-local` profile: disposable source/home/cache/resources and credential-environment exclusion are implemented; OS filesystem/network/CPU/memory isolation is not enforced.

`manifest.json` links the Topsl base commit and uncommitted source hashes, host/tool versions, exact command, Vitest outcome, generated fixture identity/base commit, candidate revisions, environment recipes/instances, protected check logs, failures, skips, support matrix, and every R2 acceptance ID. `source-hashes.json` explicitly describes working-tree bytes rather than a delivered commit. Fixture `.bundle` files preserve their disposable Git base and exact inputs; they contain only generated fixture material. Restore one into a new directory with:

```sh
/opt/homebrew/bin/git clone /absolute/evidence/offline-codex-claude.bundle /absolute/new/restored-fixture
```

The JSON outcome files archive fixture inputs and attributed attempts/retrieval receipts, exact candidate summaries, real check/environment logs, acceptance, and limitations. Vitest reports and stdout/stderr preserve unsuccessful attempts. Cleanup removes disposable execution/source directories after the outcome is archived. Encrypted runtime stores are test-only and are not published with keys.

The fault cases retain a passing result when cleanup throws, retry cleanup without another dispatch, inject a failed final storage commit without inventing a pass, reopen the encrypted vault, reject consumed-authorization replay, and reconcile the stopped execution as ineligible. A separate provider fixture loses its reply after a recorded dispatch; coordinator reconstruction cannot dispatch again. A real active check writes one effect, then awaited shutdown terminates it before vault close/reopen.

The POSIX abrupt-crash case launches a separate isolated `CheckExecutions` coordinator and a real check. After a durable log/one-effect barrier, the test sends `SIGKILL` to the coordinator. Reopening the encrypted vault retains the uncertain execution, incremental log and one consumed intent without a verification. The original recorded check PID/process group remains present, blocking reconciliation and preserving materialized roots. Only that recorded fixture group is terminated; observed absence then permits ineligible reconciliation and cleanup. The marker remains one effect, with zero replayed commands and zero durable passes. `tests/fixtures/round2-crash-worker.ts` contains the test-only worker. Windows abrupt termination is explicitly skipped until its ownership/termination path is separately implemented and executed; no production profile or provider is opened.

## Optional synthetic workload

`--stress` adds 10,000 source files of 10 KiB and four 1 MiB binary inputs to the ordinary fixture. The seed is reproducible. One hundred repeated source groups deliberately exercise deduplication; this duplicate-heavy shape does not establish arbitrary unique-data capacity. The full logical source exceeds 100,000,000 bytes. The test captures twice, requires identical content revisions, measures unique protected bytes, creates a 32 KiB initial context, reads a bounded range from the last synthetic source file, checks its expected hash, and records a cross-project denial. Retrieval uses an attributed task/session/attempt rather than a hash as authority.

The report separates generation, capture and recapture elapsed time, records process-wide sampled RSS and `resourceUsage().maxRSS`, and records SQLite size. RSS sampling can miss brief peaks, and the process includes the test runtime. This is capture/retrieval evidence on the named host; it measures no inference, UI rendering, physical disk exhaustion, remote CI or packaged platform.

The [successful standalone synthetic run](round-2-evidence/r2-6-2026-10-15T04-17-30-880Z-e5ywXu/synthetic-stress.json) measured 10,018 tracked files and 109,411,000 logical bytes on macOS arm64, Apple M5, Electron 44.4.5 / Node 24.21.0. Protected unique content occupied 8,035,000 bytes; the initial context used 32,743 of 32,768 allowed bytes. Generation took 3.798 seconds, capture 12.703 seconds, recapture 10.973 seconds, and total measured work 27.543 seconds. Process-wide sampled peak RSS was 268,648,448 bytes; `maxRSS` was 313,344 KiB, and SQLite size was 23,310,336 bytes. Two returned receipts and one denied receipt were retained. The later combined run independently passed the same workload in 19.274 seconds of measured work, with higher process-wide RSS because preceding tests occupied the same process; the reports retain both measurements rather than selecting the fastest one as a capacity claim.
