Topsl's v0.1.2 personal pilot is the first release whose Mac packages are built with the corrected signing configuration, which fixes macOS reporting the app as damaged. It also ships the Round 2 workflow engine and a way to qualify a Codex runtime for coordinated workflows.

- **Mac packages open again.** The v0.1.1 Mac ZIPs were built with signing disabled, so macOS reported the app as damaged. v0.1.2 bundles carry an ad-hoc signature and pass strict signature verification after extraction. They are still not notarized, so macOS may ask for approval under **System Settings → Privacy & Security → Open Anyway**. The v0.1.1 assets are unchanged.
- **Round 2 workflows.** Durable checks with prepared environments, protected candidate manifests and bounded retrieval, role-specific readiness, assisted native handoffs, and the guided workflow setup.
- **Runtime qualification for Codex.** **Qualify builder runtime** runs a consented suite of up to four model turns in a disposable folder and records which capabilities the runtime actually enforced. A passing run makes the builder role ready for 30 days for that exact executable, account, policy and host. Reviewer roles still need a candidate reader that is not implemented yet, and the Claude structured route cannot be qualified. The suite has been exercised only against a scripted fixture, not a live Codex runtime.
- **Project checks tolerate tool caches.** Common caches such as `__pycache__`, `.pytest_cache`, `.mypy_cache` and `.eslintcache` no longer fail a check. They are not captured as outputs, and a cache that contains a link still fails.

Downloads include macOS Apple silicon and Intel ZIPs, a Windows x64 portable EXE, and a Linux x64 AppImage. Each package has a matching `.sha256` checksum file. Extract the macOS ZIP before opening the app; on Linux, make the AppImage executable before launching it.

These packages are unsigned personal-pilot builds without Developer ID notarization or Windows publisher signing. OS publisher checks still apply. This prerelease does not certify vendor installation/update flows, live paid model execution, or complete native sidebar mirroring.

Publication requires all four platform builds, automated tests, desktop acceptance smoke tests, extracted Mac bundle verification, and uploaded-package checksum checks to pass.
