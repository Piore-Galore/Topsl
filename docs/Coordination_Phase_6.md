# Coordination Phase 6 — advanced collaboration and optional portable replication

Implemented on 14 October 2026 in the shared Topsl working tree. No live model request, subscription/API usage, provider installation/update, native credential/configuration write, release, branch, commit or push was performed for this phase. Tests use disposable local folders and generated device identities; they do not reset or modify a user's separate execution checkout.

## Advanced workflows

`packages/workflows/advanced.ts` supplies service-backed templates for independent proposals, independent test design, competing implementations, and pair debugging. Each template declares visibility, security capabilities, output types, verification requirements and repair limit. Explicit role assignments keep provider, installation and requested model reversible; automatic substitution is absent.

Independent templates require version-bound enforceable adapter capabilities for context, filesystem, tool and fresh-session isolation, plus an actual adapter access-policy installation receipt for the exact task inputs. Context packages omit peer submissions/transcripts and retain immutable approved requirements/interfaces, rubric and protocol. Production drivers have no such access-policy route, so these independent modes are gated even when their feature flag is enabled. Prompt instructions, separate worktrees and fresh sessions alone are not represented as independent isolation.

All submissions must freeze before peer comparison is exposed. Submission provenance binds task, completed attempt, artifact hash, candidate revision and protocol hash; active/uncertain writer leases prevent capture/freeze. Competing candidates start from the same captured content baseline. Exact mandatory process checks are declared before writers receive inputs, and every competing candidate must execute the same definitions before selection. Measurements require target-specific observed evidence and declared protocol input references. Selection is explicit; there is no majority vote, token-volume ranking or automatic winner.

The `advanced-capture` route captures either exact stopped candidate bytes or the completed role's attributed assistant transcript. Candidate selections enter the existing `integration-submission` queue. Acceptance of a selected artifact does not apply it to a user checkout; managed integration continues to require its own approved workspace plan and combined checks.

`advanced-check-preview` / `advanced-check-apply` create a separate tester task and use the existing digest-bound native approval, `previewCheck` and `executeCheck` paths. They preserve the original baseline harness through `bindCheckInputs`, run materialized candidate bytes with isolated task resources, and store genuine process evidence with a frozen submission/protocol receipt. OS/network sandboxing remains unavailable and is identified in the shared verification environment.

Independent test designers submit explicit JSON containing `files: [{path,text}]` and `checks: [{id,label,executable,args,timeoutMs}]`. The separate test-run stage captures a later, locally approved implementation candidate only after design freeze. Captured test bytes and the invoked check must exactly match the frozen artifact. Tests are never silently generated from a prose description or replaced by implementation-authored files. Proposals have a distinct native manual review route: the user reviews the exact frozen text and rubric, producing explicitly labelled user-confirmation evidence rather than fabricated process/model checks.

Acceptance rechecks candidate freshness, all mandatory checks and their receipts, then updates normalized Workflow/Task records. The selected task is accepted; other role/checkpoint tasks receive explicit cancellation/supersession links to the verified selection. Pair checkpoints require stopped prior turns, released leases, observed reproduction and experiment content; new immutable contexts deliver the actual evidence and driver/navigator role. Only the current driver has permitted write outputs. Final pair acceptance requires current reproduction and regression checks on the final candidate.

Routing presets persist explicit role/provider/installation/model choices and revision checks. Measurements record accepted-task rate, user-reported escaped defects, attributed retry/repair count, wall time and known usage coverage. Null/unknown usage is not invented, token volume does not rank quality, and subscription allowance remains unknown.

## Optional device layer

`packages/replication/local.ts` is a bounded portable local export/import protocol, exposed through typed service commands and native review hooks. It is not a network transport, remote execution service or live cross-device acceptance claim. The default feature flag is off; toggling it never disables trust, cryptographic, ownership or verification checks.

Each local vault owns persistent Ed25519 signing and X25519 exchange keys generated for this profile. Public fingerprints identify peers. Native approval binds an exact fingerprint and explicit project allowlist. Folder mappings require separate native folder selection, current canonical filesystem identity and confirmation. Imported workspace references contain no root or local trust; they remain unavailable/untrusted until local folder approval and still grant no execution authorization.

Portable payloads use a strict separate vocabulary: project display metadata, specifications, explicit text artifacts and logical workspace references. Native database/WAL files, native profiles/configuration, credentials, context grants, approval tokens, coordinator/lease ownership and reusable execution authorization are not serialized. Protected paths, nested sensitive JSON fields and common secret patterns are rejected. Content classification is deliberately conservative and is not a guarantee that every possible encoded secret can be recognized; exact native content review is required. The API never scans a home directory or reads arbitrary files to assemble a pack.

Transfers use X25519 + HKDF-SHA256, AES-256-GCM with fresh per-chunk nonces and authenticated transfer/index metadata, and Ed25519-signed manifests with encrypted-chunk hashes. Envelope size, chunk count and schemas are bounded. Pending chunks live in the existing encrypted SQLCipher Store and can resume after a receiver object/profile restart; duplicate chunks and completed transfer replay are idempotent. Changed manifests, unknown senders, altered chunks, invalid recipient, unapproved projects and failed GCM authentication are rejected before projection.

Three-way reconciliation records last-common observations and minimal revision ancestry. Known delayed ancestors are ignored; incompatible edits or unproven ancestry create deterministic conflicts retaining both branches until explicit native resolution. Choosing the local branch rebases its revision onto the observed remote parent, without pretending the peer has already acknowledged the choice. Owner conflicts pause authoritative work.

A local-origin owner must be designated before its first peer association. A shared project with an unknown owner cannot self-designate or execute. Once peers are associated, even a locally designated owner must receive a matching authenticated owner observation from every approved peer for that project before authoritative dispatch. Observations bind the peer fingerprint, exact local approval revision, owner and generation; reassociation, policy changes and revocation invalidate them. Association/reapproval requires all affected projects, including removed mappings, to have no active or uncertain writer lease/attempt. Two independently initialized local origins therefore both pause before their first ownership exchange; conflicting owner observations keep both paused, including when the feature flag is disabled. A previous completed transfer replay cannot restore a cleared observation. Remote metadata cannot designate a previously unknown local execution owner.

Imported owner observations never carry execution leases or grants. Authoritative service dispatch is restricted to the designated and confirmed local owner, including timer-driven provider dispatch; imported replicas cannot claim execution authority. Portable import records an ownership observation and does not establish ongoing liveness. Shared integration therefore pauses while connectivity is unproven; remote ownership transfer remains unsupported. Isolated proposals may continue under their ordinary local security gates.

Deletion removes replica content, unresolved conflict bodies, revision/common observations, pending content previews and all pending encrypted transfers. The retained tombstone is only `{id,projectId,deleted:true}`. Command receipts return identifiers/revisions instead of duplicating staged artifact content, and replication does not place raw payloads into immutable audit events. Replayed packs cannot resurrect a tombstoned identity. Already exported files held outside the local vault cannot be retroactively erased by this protocol; deletion propagates when a peer imports the tombstone.

## Verification performed

`npm run typecheck` passed. `npm test -- tests/advanced-workflows.test.ts tests/replication.test.ts` passed **20 tests** (9 advanced workflow/service fixtures, 11 portable replication fixtures).

The actual-process acceptance fixture travels through typed Service commands: common baseline → two controlled fixture attempts → captured competing candidates → exact native-approved process checks in materialized workspaces → rubric evidence → explicit selection → separate verification binding → current candidate acceptance. It rejects command substitution, absent native approval and a late outside candidate edit. No live provider/model is involved.

An independent test-design fixture freezes explicit test files/invocation, rejects implementation exposure before freeze, rejects altered tests and a changed invocation, runs an actual local regression process against a later captured implementation, binds its genuine evidence, and accepts the exact target revision. Proposal review is explicitly manual. Pair fixtures exercise uncertain turns, held writer leases, fresh checkpoint context and one permitted driver.

Replication fixtures cover generated stable identities, exact native approvals, disabled flags, unknown-owner restrictions, restart/resume, duplicate chunks/replay, unapproved devices/projects, signed-manifest tampering, chunk tampering, a correctly signed envelope with a wrong GCM tag, conflicting edits, local resolution convergence, delayed ancestor imports, tombstone propagation, deleted-payload/receipt scrubbing, protected paths/nested sensitive JSON, untrusted imported mappings, owner conflicts and safety gates after disabling a flag. Additional ownership controls exercise two independent local origins before their first exchange, a matching owner round trip, observation invalidation across reapproval/project-policy changes/revocation, old receipt replay after reapproval, and orphan active/uncertain writer leases during first association and policy removal.

The parent phase performs the final full repository check/build and desktop tests. This phase's targeted passes do not assert packaged cross-platform support, live isolation enforcement, a production structured Claude route, actual remote networking/control, physical forensic erasure of external backups/exported files, cloud deployment, or live multi-device acceptance. Those remain separate release/capability gates.
