## Build targets and channel matrix

Compilation, desktop smoke, vendor installation, and paid inference are separate results.

| Host | Topsl build target | Codex CLI | Codex desktop host | Claude Code | Claude Desktop |
|---|---|---|---|---|---|
| macOS arm64 | ZIP; local build and UI smoke exercised | Official release download; trusted CLI/stdio; adopted Homebrew update | Discover ChatGPT/Codex aliases and bundled CLI; native archive/update route | Official binary download; adopted Homebrew stable/latest update; native terminal | Official archive acquisition and native completion |
| macOS x64 | ZIP; GitHub runner target | Same routes with x64 artifacts | x64 official metadata where advertised | x64 binary / channel-aware Homebrew route | Universal macOS archive |
| Windows x64 | Portable EXE; GitHub runner target | Official ZIP; native setup; executable selection | Common user installation paths; native store/installer route | Native setup/owner update; native executable selection | Common user installation path; native installer route |
| Linux x64 | AppImage; GitHub runner target | Official musl archive; native setup; PATH discovery | Official native download/setup route; desktop discovery must be extended for each packaging channel | Official binary download; native setup/update and PATH discovery | No official native Linux application advertised; install/download disabled |

Unverified store/package deployments, custom locations, Windows Store discovery, WSL/remote hosts, Linux ARM builds, and channels outside the table are not promoted to supported structured operations. A user can locate a known native CLI executable, but doing so is not platform/channel certification. `.cmd` wrappers require selecting the actual executable; Topsl does not enable arbitrary shell interpretation to launch them.

Read-only release resolution uses the OpenAI GitHub release API for independent Codex CLI downloads and Homebrew's cask metadata for eligible official artifacts/checksums. Homebrew metadata is identified as the checksum source; it is not represented as vendor signing evidence. Native OS/installer publisher verification remains required before execution. Unknown or externally controlled native auto-update settings are displayed as unknown and are never changed.

A vendor-managed desktop's eligible update is determined by its own channel, not the public installer feed. Its update action opens the existing application. Reconciliation requires a changed version before reporting an update; a closed native flow with an identical installation is recorded as unchanged and requires a fresh review to try again. Unknown or active process state keeps the operation unresolved.

| Homebrew Claude vs bundled Codex | Tests assert the exact selected cask token and disabled refresh; bundled Codex resolves to its desktop parent |

| External update / stale approval | Content-bound executable and owner/channel revisions invalidate old previews and trust. Historical runs retain launch versions and identities |

## Remaining gates and deliberate limits

1. **Real vendor operations:** Perform disposable-machine installation/update/signature/elevation tests for each advertised OS/channel. Fixture success cannot establish native installer success. An uncertain package job may require finishing/repairing through its native owner before Topsl can confirm the approved target.
2. **Runtime policy:** Validate paid authenticated task execution, real tool approvals, sandbox enforcement, extension behavior, and native history fidelity against chosen runtime versions. Resolve Codex production eligibility before a production-supported distribution. [`scripts/live-session.mjs`](../scripts/live-session.mjs) checks one live session per provider through Topsl's interface, or a Claude Code conversation handed off to Codex, with `--qualify` runs the Codex runtime qualification, and with `--workflow` and a team runs one build and one review of a seeded project, after that qualification for a team with Codex and with each Claude Code step run from the workflow's card; [Live provider sessions](Live_Provider_Sessions.md) describes its scope and records the results.
3. **Coverage beyond tested routes:** Claude's structured route beyond one bounded live pilot ([implemented behind the owner's setting](#claude-structured-route--19-october-2026); qualified and run live once on 19 October 2026), provider-side profile isolation, live hidden-agent controls, complete effective extension policy, a structured Claude quota feed (native display reads and Codex quota snapshots are implemented; see [usage remaining](#usage-remaining--18-october-2026) and [Claude usage reading](#claude-usage-reading--19-october-2026)), API billing integrations, WSL/remote hosts, network replication, and visible native-sidebar refresh remain unverified or unsupported. Native-history reconciliation, immutable context/specification revisions, session lineage records, managed workspaces and parallel integration are implemented with fixture evidence; they are no longer described as future code. Optional advanced templates and encrypted portable metadata remain disabled by default and retain their capability/ownership gates. Portable metadata is an explicit local exchange, with no remote native control or automatic ownership transfer. Custom native sections, pins, chats and Claude project-list mutation are not mirrored.
4. **Distribution:** Add Developer ID signing/notarization and Windows publisher signing, a Topsl updater, restore/recovery UX and assistive technology tests, and packaged launch acceptance on clean OS installations. Mac pilot packages now use ad-hoc signatures with strict bundle verification before archiving and extracted-ZIP verification in both CI workflows. The repaired arm64 ZIP passed local signature verification and packaged launch/vault unlock in a temporary profile; Gatekeeper still rejects it without distribution signing/notarization. The published v0.1.1 assets remain unchanged. The tag-triggered release workflow verifies uploaded checksums and publishes a prerelease after its checks pass. It does not configure paid signing services or establish clean-machine acceptance.
5. **Scale:** Explicit legacy compatibility reads retain their bounded windows. Runtime/history streaming now sends ordered metadata invalidations and scoped snapshots/pages; catalog broadcasts contain no conversation, message, run, usage or approval arrays. History previews cap text at 6,000 characters, explicit message chunks at 20,000, and the virtual transcript mounts at most 20 rows. Both encrypted-store and real Electron 100,000-message/four-source measurements are recorded in [Phase 5](Coordination_Phase_5.md). These local fixtures do not establish a universal latency or memory SLA, continuous provider-stream acceptance, or other OS performance. After a large import, the service can be tens of thousands of change records behind, because it publishes them in order, 200 every 40 ms. A project's view no longer waits for that backlog: it refreshes from a snapshot whenever a published page names a newer record than it has replayed ([permissions plan, step 1](Provider_Permissions_Plan.md#step-1-approval-card-16-october-2026)).
6. **Ownership limitations:** Native installations can change outside Topsl. Unknown update preferences, process inventory, or compatibility stay explicitly unknown. No rollback or broader system upgrade is silently introduced.

The [v2.1 design](Topsl_Design.md) remains the complete target architecture and acceptance contract. This implementation makes its personal-pilot paths concrete without treating future phases or unperformed live acceptance as complete.

**Stall deadline (implemented the same day, stand-ins only).** A coordinated Claude turn now ends as a known failure when Claude Code stalls ([claude.ts](../packages/providers/claude.ts), `claudeStallLimits`): when nothing follows a finished model message for 3 minutes (a new message, the result or an `api_retry` notice resets it), or when Claude Code writes nothing at all for 10 minutes. Topsl then stops Claude Code, waits for its exit and records the turn as failed with the reason, so the coordinator retries the member within its retry budget; an unknown ("uncertain") outcome would instead hold the member's lease until reconciliation. Between model messages Claude Code only runs Topsl's granted tools, which return in seconds. The limits are proposed tuning values. They would have ended the two observed stalls after about 3 minutes instead of 12.5. **Interrupted turns end `interrupted` (20 October 2026, stand-ins only).** Topsl interrupts a Claude Code turn by sending it `SIGINT`, for example when a loop is stopped or paused or a round is retired. Until then every interrupted turn was reported as an unknown outcome. The runtime manager releases the turn's workspace lease only after it observes Claude Code's process group gone; otherwise the run becomes `uncertain` and keeps the lease. A turn stays `uncertain`, holding the workspace until the owner reconciles it, when Claude Code ignores the interrupt and later exits by itself, or when the stall deadline stops it. A result that arrived before the interrupt took effect keeps its outcome. The coordinator and the loop treat an interrupted member turn whose processes have stopped as ended: a stopped or paused round keeps it as stale history, and an open round records a failed contribution and retries the member within its retry budget. **Streamed message writes (21 October 2026).** The runtime manager no longer rewrites a message's whole stored text for every streamed delta, which made a long reply's storage cost grow with the square of its length. A message's first delta is written at once; later text waits in memory and is written by a per-run timer (100 ms, growing with the draft's length to at most 1 s), by the item's final message, which replaces the draft exactly, and when the run ends, including when Topsl closes. Messages keep the 2,000,000-character bound. A crash mid-stream loses at most the last timer interval of the draft; the run becomes `uncertain` on restart as before. Verified with Claude and Codex stand-ins: 20,100 deltas now cost 3 writes instead of 20,100 ([record](testing/TEST-DECISIONS.md#streamed-message-writes--21-october-2026)). Not verified in a live run.

**Equivalent-plan reconciliation (21 October 2026).** Coordinators who propose the same work in different words no longer need an owner choice.

- **When proposals combine.** Proposals for one action key combine when they agree on the action's structure: kind, role, dependencies, permitted outputs and partition scopes.
- **How wording merges.** The merged action takes the first proposer's title, every distinct brief attributed to its proposers, and the union of acceptance criteria.
- **Endorsement.** The merged candidate is no member's exact proposal, so every member endorses it explicitly and may challenge it.
- **What still needs the owner.** A structural difference, or wording too long to merge within the action limits, is still a conflict that ends with the owner's choice.

Live loop passes 5 and 6 of 19 October and the 21 October live loop each needed that choice. Verified with stand-in tests, including the 21 October live sequence (CO-02b to CO-02d). Not re-run live, and proposals that name the same work under different keys are still unioned ([record](testing/TEST-DECISIONS.md#equivalent-plan-reconciliation--21-october-2026)).

**What changed.** After [PR #38](https://github.com/Piore-Galore/Topsl/pull/38) merged, branch `claude/session-gaps` closes the gaps listed above ([plan follow-up](Native_Sessions_Plan.md#follow-up-29-october-2026)):

- **Loops in a session start from its accepted result.** `captureBase` copies the session's latest accepted result as checkpoint 0, with the project folder kept as the publication base ([Recursive Looping §18](Recursive_Looping.md#18-loops-in-native-sessions-29-october-2026)).
